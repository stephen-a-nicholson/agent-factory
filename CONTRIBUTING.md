# Contributing

Thanks for considering a contribution. A few things that keep this repo coherent:

## Before you start

- Read `CLAUDE.md` (the hard constraints: Azure Databricks/Unity Catalog/serverless only, `bundle.engine: direct` only, no PATs in CI, UK English, no em dashes, no emoji) and `docs/DESIGN.md` (the architecture and the reasoning behind it) before making a structural change.
- Check `docs/PLAN.md` for what phase the project is in and what is already decided; it also has a dated log of every real bug found while building this, which usually explains *why* something is the way it is.

## Workflow

```bash
uv sync
uv run ruff check . && uv run ruff format .
uv run pytest
uv run python -m factory.generate   # regenerate resources/generated/, must produce no diff in a clean tree
uv run python -m factory.build_template   # regenerate template/, must produce no diff in a clean tree
databricks bundle validate -t dev
uv run python -m gates.run --target dev
```

Run all of these before opening a PR; `pr.yml` runs the same checks.

## Making a change

- Prefer editing the generator (`factory/generate.py`) over adding a special case to a domain's YAML.
- Every job defined in the bundle needs a unit test for the code it runs, and should be covered by at least one quality gate rule (`gates/`).
- If you change `domain.yml`'s schema, update `factory/schema.py`, the exported JSON schema (`domains/domain.schema.json`, regenerated by `factory/generate.py`), the annotated example in `docs/DESIGN.md` section 3, and the `f1` demo domain.
- Never hand-edit anything under `resources/generated/` or `template/`; both are generated (`factory/generate.py` and `factory/build_template.py` respectively) and CI fails if either is stale.
- Do not claim something deployed or passed unless you saw the command output. If you cannot reach a workspace, say so and stop at `bundle validate`.
- Commit messages: imperative mood, one-line summary, body explaining why if not obvious.

## Reporting a bug or proposing a change

Use the issue templates under `.github/ISSUE_TEMPLATE/`. A bug report is much more useful with the exact command you ran and its output.
